# 共享 RAG 知识库

普通用户直接提问，模型按需调用检索工具查询管理员维护的共享文献库，与联网搜索一样由模型决定何时检索、检索什么，闲聊和常识问题不检索。沿用 Node / TypeScript 与 DSH 后端；SQLite 保存原文、不可变版本和中文全文索引，Qdrant 保存向量。没有普通用户上传入口，也没有失败时的演示数据回退。

## 本机准备

1. 启动 Docker，在仓库根目录运行 `docker compose -p guance-rag-backend -f server/rag/compose.yaml up -d`。固定 Qdrant 1.19.1，仅绑定 `127.0.0.1:6333`，数据保存在 Compose 命名卷。
2. 在 `server/.env` 配置 `EMBEDDING_URL`（完整 embeddings HTTP 地址）、`EMBEDDING_MODEL`、`EMBEDDING_DIMENSIONS`；需要认证时设置 `EMBEDDING_API_KEY`。本地模型服务和云端接口均可，但必须支持下述协议。模型、算力和学校连接方式尚未确定，本项目不自动下载模型。
3. `QDRANT_URL` 默认 `http://127.0.0.1:6333`；远程受保护服务可配置 `QDRANT_API_KEY`。变量全部只在后端读取。启用出站代理时，确保本机服务地址通过现有代理规则或 `NO_PROXY` 正确直连。
4. 准备 UTF-8 JSONL，运行 `pnpm rag import <文献.jsonl>`。每行一份文献，完成该文献的向量写入后才发布。随后配置回答模型密钥并运行 `pnpm chat`。

Windows 使用 WSL Ubuntu 内安装的 Docker 时，在 Ubuntu 终端进入仓库目录执行上述 Compose 命令。PowerShell 可用 `wsl -d Ubuntu -- docker version` 检查实际引擎；Windows 的 `desktop-linux` context 指向 Docker Desktop，不能用它的连接失败判断 Ubuntu 引擎不可用。后端继续在 Windows 运行时，用 `http://127.0.0.1:6333` 检查 WSL 本机端口转发；无需更改已有 Docker context 或停止其他容器。

未配置向量服务或文献库为空时不提供文献库工具，普通聊天、联网搜索和文件生成照常可用。已配置但索引未完成或检索服务失败时，工具返回明确错误，模型据此如实告知用户，具体原因写入服务端日志；无命中时工具返回“未在共享文献库中找到”，系统提示要求说明证据不足。检索尚无相关度下限：库非空时总会返回最近的片段，工具结果标题提示模型先判断片段能否支撑回答；下限待 30–50 题召回评测后再定。连接失败不会降级成纯关键词检索。

## 管理员导入与重建

这是本项目内部格式，不表示学校已提供这些字段。源库适配器应将实际字段映射到此格式；只读访问源库，不编造缺失的日期、来源或正文。

| 字段          | 含义                                          |
| ------------- | --------------------------------------------- |
| `id`          | 来源中稳定的文献标识；非空，最长 256 个字符   |
| `title`       | 原始标题；非空，最长 1000 个字符              |
| `text`        | 原始正文；非空，最长 500 万个 UTF-16 代码单元 |
| `sourceUrl`   | 可选 HTTP(S) 原始来源，不接受内嵌凭据         |
| `publishedAt` | 可选真实发布日期，`YYYY-MM-DD`；未知时省略    |

格式示例（仅用于说明，不是真实政策）：

```text
{"id":"format-example","title":"导入格式示例","text":"第一章 示例\n这是一条导入格式示例，不是真实政策。"}
```

单行最长 32 MiB；导入逐行、逐篇、每批 `EMBEDDING_BATCH_SIZE`（默认 10）个片段执行，错误立即停止并保留此前成功发布的文献。加 `--skip-invalid`（`pnpm rag import <文献.jsonl> --skip-invalid`）时跳过无效行并记录行号，结束时汇总跳过数量；超过 32 MiB 的行仍会停止导入。相同内容产生稳定版本号和片段 ID；当前版本已在当前向量空间建立索引的文献直接跳过向量化，只补做旧版本向量清理，因此中断后重新运行同一命令即可续作。向量服务的限流（429）、5xx、超时（含 HTTP 408）和网络错误（包括响应正文传输中断）按 0.5、1、2 秒退避重试 3 次，只重试失败的批次；完整但无效的 JSON、超大响应及其他校验错误立即停止。修改文献使用相同 `id`，已发布的旧版本原文保留供历史引用核对。

### 文献元数据

`pnpm rag metadata <元数据.jsonl> [--skip-invalid]` 导入按地区、规划期、文种或年份筛选所需的元数据，每行一份 UTF-8 编码的文献（含无效字节的行与其他无效行一样报错或被跳过），按 `id` 与正文对应；同一 `id` 再次导入时覆盖旧值。可在正文之前或之后导入，尚未导入正文的文献不会进入检索范围。字段沿用来源导出的命名，其余字段忽略：

| 字段       | 含义                                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| `id`       | 与正文导入相同的文献标识                                                                                              |
| `area`     | 地区层级数组，如 `["全国","安徽","六安市","裕安区"]`                                                                  |
| `level`    | 可选，`国家` / `省` / `市` / `县`；缺省时地区只有 `全国` 的文献也算国家级                                             |
| `period`   | 可选，规划期，如 `十四五`；`“十四五”时期`、`第十四个五年规划` 等写法导入时统一为 `十四五`，认不出的原样保留、只作显示 |
| `year`     | 可选，年份（1900–2100 的整数），政府工作报告按年份区分                                                                |
| `doc_type` | 可选，如 `规划文件`、`政府工作报告`                                                                                   |
| `outline`  | 可选布尔值，是否为总体规划纲要                                                                                        |

元数据只写入 SQLite，不改变文献版本和向量，无需重建索引。配置了向量服务时，命令同时为 Qdrant 集合建立 `documentId` 关键词索引（新建集合时也会自动建立），供检索按文献过滤。

`pnpm rag reindex` 逐篇确保全部当前文献在当前配置下有索引：已索引的跳过，中断后重新运行即可续作，已完成的文献在重建期间仍可检索。完成标记只记录在本 `DATA_DIR` 的 SQLite 中：Qdrant 从快照恢复或被人工修改而丢失向量时，程序无法察觉，需运行 `pnpm rag reindex --force` 全量重新向量化。`--force` 表示现有向量不可信：开始时在同一 SQLite 事务中推进当前索引的持久化代次并清除全部完成标记，重建完成前检索明确报“索引尚未完成”。检索会核对开始时的代次；即使另一个 CLI 进程在向量化、向量召回或关键词查询期间已经完成整轮重建，该次检索仍拒绝返回混用代次的结果（`RAG_NOT_INDEXED`），重试新查询即可。中途失败后运行 `pnpm rag reindex` 即可续作。更换服务地址、模型或维度通常需要重建，相同维度不代表向量兼容。集合名由每个 `DATA_DIR` 首次启用时随机生成的文献库标识与 embedding 配置指纹共同生成，多个部署共用同一 Qdrant 和模型也不会写进同一集合；复制整个 `DATA_DIR` 另起部署会沿用同一标识，不应与原部署同时运行。SQLite 完成标记还绑定 Qdrant 地址；切换模型或 Qdrant 后，全部当前文献完成索引前拒绝回答。导入确认集合丢失后，先持久化清除对应完成标记，再创建集合，避免创建成功但后续失败时沿用旧状态。更换同名模型权重、人工修改或恢复 Qdrant 数据后也应完整重建，程序无法识别服务背后的权重变化。

Qdrant 请求与索引指纹共用规范地址：去除路径末尾的一个或多个 `/`，根地址保留单个 `/`；`/proxy`、`/proxy/` 与 `/proxy///` 因而共用完成标记和重建代次，不同路径或服务地址仍相互隔离。升级本修复时，所有旧版带路径前缀的配置（包括不带末尾 `/` 的 `/proxy`）均须运行 `pnpm rag reindex`，不会复制或沿用任一旧别名的完成标记，因为旧标记可能已被另一个别名下的重建弄陈旧。常规根地址（如默认 `http://127.0.0.1:6333` 或末尾单个 `/`）保留原指纹，无需仅因升级重建；若历史上使用过根地址的 `//`、`///` 等非规范别名，升级后须运行一次 `pnpm rag reindex --force`，不能据现有完成标记判断旧向量仍可信。升级前停止旧服务和导入进程，避免不检查代次的旧进程继续回答。原文版本、发布状态与历史引用均不受这次索引迁移影响。

服务运行时可以导入：SQLite 连接等待对方的短事务（最多 5 秒）而不是报错。这一等待是同步的，会短暂阻塞服务端事件循环，因此分词在写事务之外完成以缩短持锁时间；超大文献发布时的持锁时间约在一秒以内。同一 `DATA_DIR` 只允许一个管理员导入或重建进程，使用 `rag-import.lock` 排他锁。正常结束或 Ctrl+C 会释放锁；进程被强制终止后，确认旧进程已退出再移除遗留锁文件。整个文件不做一次大事务，适合失败后重试。SQLite 发布后清理同文献其他版本的向量；清理失败会报错，重导该文献可重试。向量召回先取 80 个候选，过滤非当前版本后不足时再从头取 1000 个（不按偏移翻页，避免与导入清理删除点位竞争而漏掉当前片段），失败导入的候选因此挤不掉有效结果；1000 个候选中仍不足时明确失败，需管理员重导失败的文献完成清理。暂存失败版本、历史原文及旧模型集合不自动清理。

## 检索、引用与接口

- 检索是按需调用的工具（参照 Pinvou 的 Agentic RAG）：`library_search(query)` 由模型根据问题和上下文撰写检索词，结果不足时可换词再查；`library_open(id)` 返回一个片段及前后各一个相邻片段，已被新版本替代的片段标记 `superseded`，系统提示要求不作为现行规定引用。每次工具结果以约 6000 字为预算；`library_open` 优先完整保留请求片段，再用剩余预算展开相邻片段，按原文顺序返回并明示未展开的片段数；请求片段本身过长时仍完整返回。结果只在调用时进入上下文，不再每轮注入固定证据。系统提示要求涉及政策、规划等资料的问题先检索、只依据返回片段陈述文献事实，并用 `[原文](链接)` 引用；每个片段附所属文献的 `documentId`（即导入时的 `id`），需要写出文献编号时用它，不用片段 id 代替；检索不到时如实说明。
- 导入元数据后，`library_search` 可带可选的 `area`、`period`、`docType`、`year` 把检索限定在相应文献内；`library_list` 按同样条件（另可加标题关键词 `title`）列出文献编号、标题、地区和规划期，按规划期先后排序（无规划期的年度报告在前），最多 50 篇且受与其他检索工具相同的约 6000 字预算限制，并给出总数，供模型确认库内有哪些文献、选定篇目。地区匹配文献地区路径的任一级：有完全相同的名称时只取完全匹配，否则按前缀互相匹配（“驻马店”↔“驻马店市”、“安徽省”↔“安徽”）；“全国”只匹配国家级文献。规划期接受“十四五”“第十四个五年规划”等写法。向量检索在 Qdrant 中按文献编号过滤；关键词检索在加权 BM25 前 5000 个候选中保留范围内的片段，范围很窄（如一个区县）时关键词召回可能很少，主要依靠已精确过滤的向量召回。未导入元数据时，带筛选条件的调用如实报错，不静默忽略条件。
- 向量召回最多 80 个当前片段，FTS5/BM25 召回最多 40 个，RRF（常数 60）融合取前 8 个交给模型。关键词检索在 worker 线程中执行，不阻塞其他用户的请求；查询最多取 16 个词，分词后紧邻的单字（如“碳达峰”被切成的碳/达/峰）合成短语，被空格或标点隔开的单字（如“碳 税”“碳、税”）分别作为关键词，孤立的虚字（如“的”“和”）丢弃。查询通过临时 `fts5vocab` 视图读取当前词频；查词频前用 SQLite 原生 `unicode61` 分词，保证 `café` / `cafe` 等价拼写按同一词元统计（临时 `fts3tokenize` 与 FTS5 的 `unicode61` [保持兼容](https://www.sqlite.org/fts5.html#unicode61_tokenizer)）：有命中不超过一半已索引片段的已知单词时，去掉命中超过一半片段的词；短语、未知词和仅含常见词的查询保留，不改主库结构。标题只随每篇文献的第一个片段索引一次（权重 5）。先按 FTS5 的加权 BM25 `rank` 取前 1000 个候选，再在这些候选中按每篇最多 5 条取前 40 条，避免对全部命中片段做篇目分组排序；如果同一篇文献占满前 1000 条，实际返回可能少于 40 条。候选上限需随召回评测验证。当前版本候选按片段、版本与篇目主键读取，避免为少量候选扫描全部文献和片段。未接入重排模型，没有未经评测的相关性达标承诺。
- 检索结果是工具结果，随会话持久化，可在执行过程与轨迹中查看。原文作为不可信证据处理。回答中的原文链接只有是本会话文献工具结果中某个片段的 `link` 字段时才保留为链接，模型编造、抄错或取自片段正文与标题的路径降为纯文本；前端按整条回答中首次出现的顺序显示为上标编号，编号用与显示相同的 Markdown 解析器判断，只给真正显示为链接、且路径原样写在文本中（经过上述核对）的片段。生成文件（如 `.md`）中的片段路径不经此核对，预览时按普通文字显示。
- `GET /api/library?limit=50&offset=0` 返回 `{total, documents}`，每页 1–100 篇。
- `GET /api/library/passages/{UUID}` 返回可阅读原文页，`?format=json` 返回片段数据。所有文本转义且页面禁止脚本；Markdown 仅额外允许精确原文相对链接。业务接口经过现有身份验证，未发布片段返回 404。

原文页显示章节、版本、日期和来源链接；文献更新后，旧引用打开的原文页标明“已被新版本替代”，不当作现行文本。检索结果在模型作答期间也可能因导入发布新版本而过时，这一时间差无法在检索时消除，由原文页的版本状态提示。`start`、`end` 是 `text.slice(start, end)` 的 UTF-16 偏移，不能当作 PDF 页码或字节位置。每块最多 1600 个代码单元，长段最多重叠 160。按编、章、节、条及 Markdown 一至四级、“一、”式标题分节；标题行并入其后正文，不单独成块；款、项（“（一）”“1.”）留在所属条内，超长时按段落或句子切分；不足 300 字的节与下一节合并，片段标题取合并各节共同的章节路径。章条、段落识别和 300 字阈值基于规则，需在学校真实文本和召回评测上校准；切块规则变化会让每篇文献产生新版本，宜在导入学校语料前定下。文献库主页面待 UI 任务接入列表 API；本分支仅增加回答中的引用链接和独立阅读页。

## 协议与部署边界

Embedding 发送 `{model,input,dimensions}`，接收 `data[].index` 与 `data[].embedding`。默认每批 10 条（部分服务如 DashScope text-embedding-v3/v4 单次上限为 10，以所选服务文档为准，用 `EMBEDDING_BATCH_SIZE` 调整）、30 秒超时，导入时对临时错误退避重试 3 次，检索时重试 1 次，校验数量、索引、维度和有限非零向量。Qdrant 使用 Cosine 距离和等待写入完成的 API。停止生成取消向量化和检索请求。部署前须用所选服务验证协议，测试向量不证明真实语义效果。

Compose 是本机开发配置。正式部署需设置 Qdrant 私网访问及认证，不把 6333 端口暴露到公网。备份前停止回答和导入任务，备份整个 `DATA_DIR`，同时备份 Qdrant 卷或使用其快照。两者一起恢复，或恢复原文后完整重建向量。模型 API 和服务器费用独立于 Qdrant 开源软件许可。

自动测试覆盖切块、不可变原文、协议错误、索引发布、混合检索、取消、身份边界、模型上下文与引用。启动本机 Qdrant 后可单独运行 `pnpm test:rag`，以受控测试向量验证真实数据库协议；使用随机测试集合并清理，不读取 `server/.env`，不调用真实模型。该检查独立于不依赖 Docker 的 `pnpm check`。

已用本机 BGE-M3 与 Qdrant 在 39,585 篇文献、980,124 个片段上完成检索对照评测：调参集 549 题、留出集 222 题计分，两组均包含题目原文与参考作答检索词。查询优化后的单次检索中位数 / 95 分位分别为 1.03 / 1.64 秒和 0.96 / 1.57 秒，篇目与要点原文片段召回均与 main 基线一致；运行记录在仓库外的 `rag-eval/PLAN.md` 第六节。全库 DeepSeek 回答、十人并发和 120 秒回答响应目标尚待验收；学校 SQL/API/导出方式仍未提供。
