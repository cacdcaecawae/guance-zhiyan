# 开发流程

```
阅读现状 → 澄清范围与验收 → 按需记录术语 / ADR
→ 小步实现并补测试 → 本地检查与差异审查 → CI → 人工验收
```

手续随任务大小伸缩：文案、样式、单处缺陷这类小改动可以跳过第 2、3 步，直接实现并检查；新功能和接口变化走完整流程。

1. **阅读现状**：看相关代码与 `AGENTS.md`；运行 `git status`，保留别人未提交的改动。
2. **澄清范围与验收**：写清目标、不做项和验收方式；涉及数据时说明接口与异常状态（加载 / 空结果 / 失败）。写在任务说明或 PR 中即可，不强制单独写 spec。推断不出又会影响方案的信息先问清楚，其余按合理默认处理，并在 PR 中写明假设。
3. **按需记录术语 / ADR**：新术语写进 `CONTEXT.md`（只放术语表）。难以撤销、缺少背景会令人意外、经过真实取舍，三条同时满足才写 `docs/adr/NNNN-title.md`，引入影响全局的依赖一律视为满足；修订已有决定就更新原 ADR，推翻已有决定时新建 ADR，并在旧 ADR 中注明被取代。功能细节与验收结论不写进这两处。用 grill-with-docs 等工具澄清得到的术语与决定，同样按这里的规则写入。
4. **小步实现并补测试**：一次只做一件事，行为变化配上针对行为的测试。
5. **本地检查与差异审查**：`pnpm check` 通过后，用 `git status` 和 `git diff` 看一遍全部改动，确认没有硬编码颜色和未标注的演示内容。
6. **CI**：PR 描述按 `.github/pull_request_template.md` 填写；开 PR 或推送到 main 时，GitHub Actions 运行同样的 `pnpm check`，失败时下载 Playwright 报告排查。
7. **人工验收**：审阅者按 PR 中的验收步骤在浏览器里操作，检查浅色 / 深色、宽屏 / 窄屏；涉及回答或资料面板时，再用长回答和长链接试一下。

## 后端与测试

应用只有真实后端路径，界面通过 `src/services/` 请求本项目 `/api`。`pnpm chat` 提供显式本机免登录入口，仅监听 `127.0.0.1`，请求来源校验通过后使用固定本机身份。`server/auth.ts` 保留学校身份边界，普通启动未接入认证时返回 401。不要把测试身份接入生产，也不增加失败时的演示回答。

`pnpm test` 包含前端单元测试及 `server/*.test.ts` 后端集成测试；`pnpm test:e2e` 构建前端并自动启动隔离测试后端与 Vite，另测正式本机启动进程。受控模型在 `tests/support/model.ts`，仅测试代码注入；文件工具、持久化与 HTTP 链路仍运行实际实现。本机入口测试只替换外部模型协议服务，使用实际启动入口、身份边界和 DSH 适配器。测试目录使用系统临时路径，用完清理；测试不得使用真实用户数据或密钥。

会话归属、SSE、停止与文件下载行为变动需覆盖相应回归。受控协议测试不能替代真实 DeepSeek 与搜索端点验收，交付时分别说明。启动配置、备份和部署限制见 README。

后端测试启用 `--expose-gc --test-isolation=none`，在单个测试进程中强制垃圾回收，验证两家供应商的原生 SSE 仍能及时停止。DSH 的解析流取消补丁通过 `pnpm-workspace.yaml` 固定，见 `THIRD_PARTY_NOTICES.md`；升级依赖时须保留该回归。

## 多人并行

- 已知有人在改同一接口（`src/types/`、`src/services/`）时先协调；否则直接改，在 PR 中列出接口变化
- 并行任务各用独立分支或 `git worktree`，新 worktree 先运行 `pnpm install`
- 浏览器测试固定使用 3001（测试后端）、3002（正式本机入口）和 4173（前端）端口，同一时间只能在一个工作目录运行，先停止占用这些端口的服务

## 首次环境准备

```bash
corepack enable                          # 匹配 package.json 中的 pnpm 版本
pnpm install
pnpm exec playwright install chromium    # Linux 加 --with-deps
```
