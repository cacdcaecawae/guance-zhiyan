# ADR 0006：管理员维护的共享 RAG 知识库

日期：2026-09-26 · 状态：已接受（源库接入与向量模型待校方条件确定）

## 背景

路线图中的“文献上传”未明确使用者。本轮澄清确认：普通用户使用提前准备的知识库，系统默认调用 RAG；资料导入由管理员负责。

本文记录架构决定，具体能力与运行边界见 [RAG 开发说明](../RAG.md)。

用户提供的《附件2：参赛指南》截图（印刷页码 7）说明了现有数据条件：

- 校内规划文本库可提供只读访问，现有检索以关键词为主。
- 共 53,161 篇，其中规划文件 40,744 篇、政府工作报告 12,417 篇。
- 正文总字数约 12.17 亿字，数据库正文文本覆盖率为 98.9%。
- 来源为政府网站公开发布的电子原生文件，非扫描件，材料说明无需大规模 OCR。
- 材料提出集中式线上部署、校内并发 10 人、单次问答 120 秒内的目标，并说明三个月内工作量可控。

以上为材料所述条件，尚未通过实际数据或运行测试核验。源库的访问方式、字段结构、更新标识与导出能力仍未知；材料没有说明已提供向量索引或可直接调用的 RAG 接口。

用户补充：学校目前尚未明确向量化模型的部署方式或提供何种算力，因此不将已有校内部署条件作为设计前提。

参考项目 Pinvou 的现有实现是在本机或其知识库服务器上运行 BGE-M3 INT8 ONNX，以 SQLite 全文检索结合稠密向量检索；它的远程知识库不等于商业 embedding API。本项目尚未决定沿用这一部署方式。依据：[向量化实现](https://github.com/Pinvou/pinvou-agent/blob/ba15df412b83cb5650b07006e8c90ff28a0215ec/pinvou-knowledge/src/embedding.rs)、[检索实现](https://github.com/Pinvou/pinvou-agent/blob/ba15df412b83cb5650b07006e8c90ff28a0215ec/pinvou-knowledge/src/store.rs)。

## 已确认的决定

- RAG 使用管理员提前准备和维护的共享知识库。
- 普通用户直接提问，默认使用知识库检索，无需上传文献或手动开启 RAG。
- 文献导入属于管理员操作；具体导入方式尚未决定，不预设管理页面或上传接口。
- 本轮不建设普通用户上传文献形成个人知识库的流程。
- 先按通用 RAG 流程设计，沿用路线图中的关键词与语义混合检索、回答附原文引用；不以获得全库文本为开始设计的前提。真实样本用于验证接入、切块、引用定位和检索效果。
- 用户同意先完善后端功能，具体向量化模型随后确定。向量化采用后端 HTTP 接口，配置指纹包含服务地址、模型与维度；更换这些配置后，需验证或重建对应索引，不能默认旧向量兼容。

2026-09-26 用户明确同意采用 Qdrant + SQLite。保留已经存在的 Node / TypeScript 与 DSH 后端，不按早期路线图另建 FastAPI 服务。

## 向量索引存储

增加 Qdrant 服务，使用其现成向量索引；后端通过 HTTP 调用，无需在浏览器接入或新增前端依赖。开发时使用 Docker 并仅绑定本机地址，正式部署时放在后端可访问的私有网络。

SQLite 继续保存用户、会话、文献版本、原文片段和全文索引；Qdrant 保存从片段派生的向量索引。该方案增加独立服务、磁盘目录及备份维护，模型切换还需要重建兼容的索引。它优先复用成熟的向量搜索实现，避免为全库自行编写逐条向量扫描或近似索引算法。

采用关键词与向量双路召回及 RRF 融合，重排模型留待评测。管理员通过内部 JSONL 格式导入，学校实际数据结构另做适配，不提前建立网页上传入口。每轮回答前检索，未配置、空库、索引不完整或检索失败时明确报错。

根据本轮提供的资料，数据接入按读取校方现有原文库考虑；管理员侧的工作重点是数据导入或同步与检索索引维护，不修改校方源库。

## 后果

文献归属于共享知识库，不能直接沿用“当前用户、当前会话的生成产物”作为文献存储模型。共享知识库不改变 ADR 0004 已定的用户会话与产物隔离。

片段绑定不可变文献版本，更新后旧引用仍可核对。向量写入完成才发布文献，检索核对 SQLite 当前版本；模型配置变更使用独立集合并要求完整重建。后续需确认源库接入方式、样本结构、同步更新标识及 embedding 部署。现有数据规模须纳入索引构建、召回和并发测试。
