# ADR 0004：多人会话后端与 DSH Agent 循环

日期：2026-09-23 · 状态：已采纳（用户已确认完整方案）

2026-09-24 补充：用户确认第一版先打通本机聊天，无需登录操作，学校认证继续待定。增加 `pnpm chat` 显式本机入口：强制回环监听与同源访问，后端赋予固定本机身份；不新增账号密码或注册系统，不作为公开多人部署方案。普通服务器入口继续保留认证边界，未接入可信身份时拒绝访问。

## 确认进度

2026-09-24 界面修订：用户要求整体参照 DSH，对话采用紧凑执行过程，增加独立轨迹页签展示真实消息与工具时间。两个视图继续由同一份会话日志派生，不引入 DSH 全套前端插件运行时。出站网络复用同版本 DSH HTTP 代理组件以支持本机 fake-IP 网络，保留其公网地址检查。

2026-09-24 补充：用户确认同时接入 DeepSeek 官方与千问 AI 平台提供的 DeepSeek 模型，网页选择供应商和模型。后端维护已核对的模型允许列表、独立密钥与端点；每个供应商使用独立 DSH 适配器，每次执行隔离联网工具配置。SQLite 增加会话的供应商与模型选择，历史仍只由 DSH 日志维护。切换供应商时会话历史发送至所选平台，失败不自动转用另一供应商。当前模型与参数见 README。

用户已确认：Node.js / TypeScript 后端；以 DSH Standard 为参考、仅一个综合助手配置；多人独立账号、会话与文件；首版只调用内置工具，不开放 Bash / 任意代码执行。账号开通方式暂时待定，后续可能对接学校官方身份系统，后端先明确模块职责。

用户已确认将联网搜索、网页读取纳入第一版内置工具。工具执行方式与功能范围分别决定：这些工具由后端预先实现并校验请求，不向模型开放 Bash 或任意代码执行。首批产物格式为 Markdown、Word、Excel/CSV；PDF 和 PPT 暂缓。

用户已确认存储分工：SQLite 保存内部用户、会话归属与文件索引；DSH 原生日志保存问答、工具调用及执行历史，作为会话历史的唯一事实来源；产物文件单独保存。备份须同时覆盖数据库、会话日志和产物文件。

用户已确认删除演示模式：真实后端为唯一运行路径，移除内置虚构会话、回答和引用，以及相关演示入口与文案；失败不得回退到模拟数据。自动化测试可以使用明确隔离的模型测试替身，不作为应用运行模式。

逐项功能取舍与验收范围已澄清，并已取得用户整体确认，grill 澄清完成。账号开通和认证提供方明确延期决定，不默认为管理员创建或自助注册。当前实现与运行限制以 README 和代码为准。

## 背景

此前仓库只有前端演示，没有后端接口。FastAPI 是路线图中的候选方案，尚未实现。此次需求从纯会话明确为服务器上的研究助手：多轮问答、工具执行过程与文件产物。用户希望尽量复用 DeepSeek Harness（DSH）的前端与 Agent Loop，采用一个综合助手，并确认多人使用时账号、会话、文件独立，首版只调用内置工具。

本决定扩展 ADR 0001 的前端工程基线，并替代 ADR 0002 中会话暂不持久化与演示模式的阶段性安排；`src/services/` 作为界面唯一数据入口的约束继续有效。

## 决定

- 在 `server/` 新建 Node.js / TypeScript 后端，保留当前 React 前端与设计系统。原生 DSH 模块使用 TypeScript，因此优先直接集成其循环，避免重新用 Python 实现同一流程。
- 以 DSH 的 Standard 预设作为能力与交互参考，实际只组装循环、模型适配器、会话和本项目内置工具。只有一个综合助手配置，不提供 Standard / PTC / Minimal / Creator 切换。
- 直接复用 `@deepseek-ai/dsh-agent-loop`，配套的 DSH 包锁定相同版本。核对基线为 `0.1.7-rc.1`、源码提交 `46a7f68b0922371ce7144b668b90e377d8e799f4`；禁止混用不同默认发布标签。
- 使用底层 Agent 的取消能力，不以关闭共享 SDK 子进程实现停止。SDK 的当前协议没有逐会话取消方法，不适合直接承担多人网页的停止按钮。
- SQLite 保存内部用户、会话归属和文件索引，产物文件单独保存；会话事件交由 DSH 原生持久化维护，作为消息历史的唯一事实来源。网页消息与工具过程从事件派生，不再维护第二份可写消息数据库。
- 后端按职责划分身份认证、会话与执行、内置工具、文件产物。认证部分负责确认请求者身份；会话和文件归属统一使用项目内部用户 ID。具体认证提供方与账号开通方式待学校对接要求明确后决定，不预先引入 SSO SDK、协议配置或多套登录实现。
- 每次会话读取、发送、停止、文件读取和下载均检查当前已认证用户的归属，身份不采信浏览器随意填写的用户 ID 或模型参数。未来学校认证只提供可信身份，不代替业务层的访问控制。认证未接通前不得把开发测试身份入口作为公网登录方案。
- 内置工具首批包含联网搜索、网页读取，以及会话内文件读取与产物生成。首批生成格式为 Markdown（`.md`）、Word（`.docx`）、Excel（`.xlsx`）和 CSV（`.csv`）；产物有名称、类型和大小。Word 与 Excel 使用对应生成器产生真实文件，不能仅改扩展名；PDF 与 PPT 不在本次范围。
- 不加载 Bash、PowerShell、任意代码执行、插件安装或子 Agent 工具。以后增加专用工具走工具注册入口；增加通用代码执行需要单独决定隔离环境、资源预算和文件权限。
- 2026-09-24 根据用户反馈修订：Agent 执行与联网工具采用 DSH 默认参数，移除应用额外添加的 8192 输出 tokens、任务数、步骤数、工具调用总次数、总时长、分片数和 JSON 字符上下文限制。保留同一会话只执行一个任务，防止历史交错，以及身份归属、输入校验和 DSH 公网地址检查。首版按单服务进程部署；多实例共享存储与分布式调度不在此次范围。
- 前端参考并选择性移植 DSH 的思考折叠展示逻辑，保留来源和许可证；工具过程与文件卡片适配本项目数据入口和语义 tokens，不整体引入 DSH 的前端插件框架。
- 模型接口提供的思考内容与实际工具事件分别显示；失败、中止和完成是不同状态。模型文本与网页内容均作为不可信数据处理，不作为 HTML 或脚本执行。文件预览与文件生成分别实现，不把支持下载某种格式等同于已支持其完整预览。
- 删除演示模式、内置虚构会话与引用和相关文案；真实后端为唯一应用运行路径。缺少密钥、请求失败、历史为空或功能未实现时显示实际状态。测试替身仅由测试代码注入，不作为部署配置开放。

## 本次验收

- 两个账号无法读取、修改或停止对方的会话，不能访问对方产物。
- 本机入口无需登录可完成真实模型请求；仅允许本机同源访问，并阻止外站嵌入。普通服务器入口在认证提供方未决定期间拒绝无可信身份的请求，以测试注入的身份验证多人隔离。学校登录接入及公开多人上线不属于本次完成承诺。
- 在网页完成多轮问答、流式回答、停止和失败后重试；刷新和服务重启后可恢复历史，中断不得显示完成。
- 模型真实调用内置工具时，网页显示工具开始、结果或失败；生成的文件可以下载，内容与生成结果一致。
- 联网工具返回可核对的网页来源，网页内容按不可信输入处理；Word 与 Excel 文件通过对应解析器校验内容，Markdown 与 CSV 校验实际文本。
- 使用受控模型适配器测试原生循环、工具调用、取消与恢复；通过后端集成测试和浏览器测试覆盖账号边界与交互。没有真实密钥时明确记录尚未进行真实 DeepSeek 验收。
- 执行 `pnpm check`，检查浅色 / 深色与宽屏 / 窄屏。

## 后果

- 复用成熟的循环与会话机制，但引入 Cordis 及 DSH 的配套依赖，需要一起维护版本与兼容性测试。
- 账号/产物数据库和原生会话日志需要一起备份；不把同一份会话历史同时写入两套存储。
- 本次范围为会话、联网搜索、网页读取与文件产物工具；自有文献库的 RAG、原文片段引用和跨文献研究流程仍按后续阶段实现，不把网页来源冒充文献库检索结果。
